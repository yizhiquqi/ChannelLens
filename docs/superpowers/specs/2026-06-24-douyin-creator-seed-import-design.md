# 抖音达人首批样本公开导入设计

## 目标

将已采集的 30 位抖音达人作为首批公开样本导入 ChannelLens 正式网站，用于验证品牌方是否会浏览、搜索和进一步了解达人档案。

## 范围

- 导入 30 位达人：美妆护肤 15 位、食品饮料 15 位。
- 复用现有 `admin_partners` 表、公开合作方列表和详情页。
- 所有记录设置为 `public`，无需后台审核后再发布。
- 核对并保留现有“0 分显示暂无评分”逻辑。
- 对未核验且没有风险标签的档案显示“风险待评估”，不能因为必填兼容字段为 `low` 而对外显示“低风险”。
- 在详情页展示可点击的抖音公开主页来源链接。
- 不新建达人专用数据表、页面或复杂筛选功能。

## 数据口径

每条记录使用固定、可重复导入的 ID。达人 ID 使用 `p_douyin_001` 至 `p_douyin_030`；公司档案继续使用 `p_company_...`，不得混用。每条记录包含以下公开字段：

- 达人昵称
- 实体类型：个人
- 角色：抖音达人
- 平台：抖音
- 主品类与内容标签
- 粉丝数（2026-06-24 搜索页快照）
- 公开简介摘要
- 抖音主页链接
- 数据来源与采集日期
- 核验状态：未核验
- 可见性：公开

缺失字段统一使用“待补充”或空值。评分各维度保持 0，合作案例、互动率、报价、地区、MCN 归属和风险结论不作推测。

不写入或展示公开主页中的微信号、手机号、邮箱等联系方式。

## 展示规则

- 列表页和详情页显示“未核验”和公开数据来源。
- 总评分为 0 时显示“暂无评分”，避免用户误认为达人获得了 0 分评价。
- 未核验且没有风险标签时显示“风险待评估”。
- 详情页提供抖音公开主页链接，供用户自行复核。
- 不生成合作评价、成功案例或风险标签。
- 主页链接用于用户自行复核公开来源。

## 导入方式

使用 `p_douyin_001` 至 `p_douyin_030` 将 30 条记录写入 Supabase 的 `admin_partners`，并同步 `partner_visibility` 为 `public`。采用 upsert，重复执行不会创建重复记录。

线上写入使用当前管理员身份和现有 RLS 策略完成，不引入服务端密钥或绕过权限。

## 失败处理

- 写入前读取同一批固定 ID，确认不会覆盖无关数据。
- 任一批次写入失败时停止，不继续写入后续批次。
- 写入后核对数据库公开记录数为 30，并抽查至少 3 条记录。
- 若页面展示异常，保留数据库记录但不继续部署代码；先修复并重新验证。

## 验证标准

1. Supabase 中 30 条固定 ID 记录均为 `public`。
2. 未出现重复达人记录。
3. 公开列表能够搜索到美妆与食品达人。
4. 至少抽查 3 个详情页，昵称、粉丝数、简介、来源链接正确。
5. 未核验达人显示“暂无评分”，不显示虚假案例、评价或联系方式。
6. 本地构建和必要测试通过。
7. 页面口径调整通过本地检查后提交 GitHub，Vercel 部署成功并完成线上复核。

## 不在本次范围

- 自动定时更新抖音粉丝数。
- 批量爬取视频、评论或互动数据。
- 自动生成达人评分。
- 自动发送合作邀约。
- 新建达人专用频道或收费功能。
